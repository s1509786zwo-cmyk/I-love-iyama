## 1-4. インポート手順（共通）

1. **UnityPackage の場合**：Unity上部メニュー `Assets > Import Package > Custom Package...` → ファイル選択 → 全部チェックして `Import`。
   （Asset Store購入品は `Window > Package Manager > My Assets` から Download → Import）
2. **FBX の場合**：Projectウィンドウにフォルダごとドラッグ＆ドロップ → モデルを選択し Inspector の `Rig` タブは触らず、`Model` タブで `Scale Factor` が実寸（家なら高さ3〜6m程度）になるよう確認。
3. **まずサンプルシーンを開く**：アセットのフォルダ内にある `.unity`（Scene）ファイルをダブルクリック。いきなり自作シーンに部品を置くより、作者の完成形を歩いてみるのが近道です。
4. **ピンク色になったら**：マテリアルのシェーダーが今のプロジェクト用でない証拠です。
   - **Built-in RP プロジェクトならほぼ起きません**（BOOTH/VRChatアセットはBuilt-in前提）。だから本作は **Built-in RP（3Dテンプレート）で始めるのが正解** です。
   - URPで始めてしまった場合：`Edit > Rendering > Materials > Convert Selected Built-in Materials to URP`（Unity 6では `Edit > Render Pipeline` 配下）で変換します。

# 【2】高品質アセットを使っても「絶対に重くしない」最適化手順

## 全体の考え方（30秒で理解）

処理が重い原因は主に4つだけです。**①テクスチャがでかい ②ライトが毎フレーム計算している ③見えない物まで描いている ④遠くまで描いている**。以下の4手順はこの順に潰していきます。作業前に `File > Save As` でシーンのコピーを残しておくと安心です（例：`Kominka_Test`）。

> 計測方法を先に覚えましょう：Gameビュー右上の **`Stats`** ボタンをON。再生中の **FPS / Draw Calls（目標：室内で200以下）/ Tris（目標：50万以下）/ SetPass calls（目標：100以下）** を見ながら作業すると、効果が数字で分かります。

---

## 2-1. テクスチャ解像度の一括圧縮（4K → 1024〜2048）

### 方法A：付属ツールで一括（おすすめ・30秒）
1. 上部メニュー **`Tools > Mimi Horror > Texture Batch Optimizer`** を開く
2. 「対象フォルダ」にアセットのフォルダ（例：`Assets/Furuyamura`）をドラッグ
3. 通常テクスチャ **1024**、法線マップ **1024** のまま **`一括適用する`** を押す

### 方法B：手動（仕組みの理解用）
1. Projectウィンドウでアセットのフォルダを開き、検索欄に `t:Texture2D` と入力
2. `Ctrl + A` で全テクスチャを選択（複数選択のままInspectorを編集できる）
3. Inspector の **`Max Size` を 1024** に、**`Compression` を Normal Quality** にして `Apply`
4. 主役級のテクスチャ（人形の顔、襖絵など）だけ後から個別に **2048** へ戻す

**ポイント**
- これは元画像を消す作業ではなく「Unity内での取り込み上限」なので、**いつでも元に戻せます**。怖がらずに落としてOK。
- `Generate Mip Maps` は3D用では必ずON（遠くの畳の目のチラつき防止と軽量化を兼ねます）。UI画像だけOFF。
- 壁・床・畳など広い面でも1024で十分。**暗いホラーでは懐中電灯の円の中しか見えない**ので、解像度不足はほぼバレません。これが本作の最大の味方です。

## 2-2. ライティングのベイク（家の明かりは焼き込む、懐中電灯だけリアルタイム）

### 手順① 家全体を「動かない物」として登録する
1. Hierarchy で家のルートオブジェクト（例：`Kominka`や`House`）を選択
2. 上部メニュー **`Tools > Mimi Horror > 1. Apply Static Flags to Selection Hierarchy`**
   （手動の場合は Inspector 右上の **`Static`** のチェックを全項目ON）
3. **例外**：開閉する襖・ドア、動かす予定の人形など「動く物」は選択して Static を外しておく

### 手順② 家のライトを全部「Baked」にする
1. Hierarchy の検索欄に `t:Light` と入れて全ライトを表示
2. 太陽（Directional Light）や部屋の電球などを1つずつ選び、Inspector の **`Mode` を `Baked`** に変更
3. 室内が舞台なら Directional Light は**削除してOK**（月の明かりを障子越しに入れたい場合は Baked で残す）

### 手順③ ベイク設定を開いて焼く
1. 上部メニュー **`Window > Rendering > Lighting`** → 下部の **`New Lighting Settings`** → `Create`（初回のみ）
2. **Scene** タブで以下に設定（低スペック向けのおいしい設定）：

   | 項目 | 設定値 | 理由 |
   |---|---|---|
   | Lightmapper | Progressive GPU（なければCPU） | 速い方でOK |
   | Lightmap Resolution | **10〜20** texels/unit | 40は綺麗だが重い。暗い家なら15で十分 |
   | Lightmap Size | **1024** | メモリ削減 |
   | Ambient Occlusion | ON（任意） | 隅の汚れ感が増してホラー向き |

3. **Environment** タブ：`Environment Lighting > Intensity Multiplier` を **0.1〜0.3** まで落とす（家の基礎の暗さ）
4. 一番下の **`Generate Lighting`** を押す。数分かかるのでコーヒー休憩。
5. 焼き終わったら、ベイク済みライトは**再生中の計算コストがほぼゼロ**になります。

### 手順④ 懐中電灯だけをリアルタイムにする
- プレイヤーの `Flashlight` の Light は **`Mode: Realtime`、`Shadow Type: Soft Shadows`** のまま（付属のPlayer Rigは最初からこの設定です）。
- **影を出すリアルタイムライトは、この1灯だけ。** これが守れれば低スペックでも60fpsが狙えます。
- 確認用ツール：**`Tools > Mimi Horror > 3. Report Realtime Lights`** を押すと、Consoleに「今リアルタイムなライト一覧」が出ます。懐中電灯以外が出たらベイク漏れです。

> ⚠️ 注意：ベイクした後に家や家具を動かすと影がズレます。**配置が決まってから焼く**のが順番です。開発中は「配置→焼く→テスト」を繰り返します（焼き直しは `Generate Lighting` を押すだけ）。

## 2-3. オクルージョン・カリング（襖の向こうの部屋を描かない）

1. 上部メニュー **`Window > Rendering > Occlusion Culling`** を開く
2. **Bake** タブで設定：

   | 項目 | 設定値 | 意味 |
   |---|---|---|
   | Smallest Occluder | **1** | 壁として扱う最小サイズ（m）。家なら1で十分 |
   | Smallest Hole | **0.25** | この大きさの隙間は「覗ける穴」として残す |
   | Backface Threshold | 100 | 既定値のまま |

3. **`Bake`** ボタンを押す（2-2手順①で Static 化した壁・床が「遮る物」として使われます）
4. Main Camera の Inspector で **`Occlusion Culling`** にチェックが入っているか確認（Player Rigは最初からON）
5. テスト：同ウィンドウの **Visualization** タブを開いたまま再生し、Sceneビューで家を上から見ると、**今いる部屋以外が非表示になっていく**のが目で確認できます

**ポイント**
- 日本家屋は「壁と襖で細かく区切られた小部屋の集まり」なので、オクルージョンが**異常に効く**構造です。Draw Calls が半分以下になることも珍しくありません。
- 開閉する襖を Occluder Static にすると「開けたのに向こうが描かれない」バグになります。**動く扉は Static から外す**（2-2手順①の例外処理がここで効きます）。

## 2-4. 暗闇フォグ＋描画距離の短縮（軽量化と恐怖演出の一石二鳥）

### ワンクリック版
**`Tools > Mimi Horror > 2. Setup Horror Darkness (Fog + Far Plane)`** を押すだけ。以下が一括設定されます（後から手動で微調整可）。

### 手動版（各値の意味）
1. **`Window > Rendering > Lighting > Environment`** タブ → **`Fog`** にチェック
   - Color：ほぼ真っ黒 `#010102`
   - Mode：`Linear` / Start：**2** / End：**16**（16m先は完全な闇）
2. **Main Camera** の Inspector：
   - `Clipping Planes > Far` を **25**（25m以遠は描画自体をやめる）
   - `Background` の色を **Fogと同じ黒** にする（重要：ズレると遠景の輪郭が見えて興ざめします）

**ポイント**
- フォグ自体は「隠す」だけ、**描画負荷を下げるのは Far の短縮とオクルージョンの合わせ技**です。「フォグ＝ポップイン（突然現れる現象）を闇で誤魔化すカーテン」と覚えてください。
- 廊下の突き当たりが常に見えない距離感は、和風ホラーとして完璧な演出でもあります。**軽くするためにやることが、そのまま怖くなる**のが本作の設計です。

## 2-5. あと少し効く小技（全部ワンクリック級）

| やること | 場所 | 効果 |
|---|---|---|
| Pixel Light Count を **2** に | `Edit > Project Settings > Quality`（Built-in） | 1つの物に当たるリアルタイムライト上限。懐中電灯中心なら2で十分 |
| Shadow を「Hard Shadows Only」or 解像度 Medium | 同上 Quality | 影の計算を軽くする |
| Anti Aliasing を 2x か Disabled | 同上 Quality | 低スペックの味方。暗い画面では切っても目立たない |
| 当たり判定は BoxCollider で自作する | 家の壁・床 | MeshCollider は重い。床と壁は薄いBoxで十分当たりが取れる。小物にはColliderを付けない |
| 同じ小物（畳・座布団等）のマテリアルで `Enable GPU Instancing` ON | Material の Inspector 一番下 | 同一モデルの大量配置が軽くなる |
| テスト用ビルドで確認 | `File > Build Settings > Build` | エディタ再生より実ビルドの方が正確かつ速い。60fps判定はビルドで |

# 【3】超軽量・一人称探索コントローラー

## 3-0. 最初の1回だけの設定
1. `Assets` フォルダを自分のUnityプロジェクトの `Assets` へコピー（フォルダ構成を保つこと。`Editor` フォルダ名は変えない）
2. `Edit > Project Settings > Player > Other Settings > Active Input Handling` を **`Input Manager (Old)`** または **`Both`** にする（旧来の `Input.GetAxis` を使うため。変更するとUnityが再起動します）

## 3-1. プレイヤーを作る（ワンクリック）
1. 家のサンプルシーンを開く
2. **`Tools > Mimi Horror > Create Player Rig (FPS)`** を押す
3. シーンに最初からある別の `Main Camera` が残っていたら**削除**する（カメラは1台だけ）
4. 生成された `Player` を選択し、玄関や土間などスタートしたい場所の**床の上**に移動させる（Playerの原点＝足元です）
5. 再生ボタン ▶ でテスト

### 生成される階層と各役割
```
Player                        … CharacterController（身長1.7m）＋移動と調べる判定
├─ CameraHolder               … 上下の視点回転担当（目の高さ1.6m）
│  └─ Main Camera             … Far=25m、背景=真っ黒、Occlusion ON 設定済み
└─ Flashlight                 … Spot Light（このシーン唯一のリアルタイム影ライト）
```
> なぜ懐中電灯をカメラの「子」にしないのか？ 子にすると視点と完全同期して機械的に見えます。付属スクリプトは `LateUpdate` でカメラに**僅かに遅れて追従**するため、手で持っている生々しさが出ます。遅れが嫌なら Inspector の `Enable Lag` をOFF。

## 3-2. 操作方法（初期設定）

| 操作 | 動作 |
|---|---|
| `W A S D` | 歩く（2.2 m/s） |
| `Shift` + 移動 | 早足（3.8 m/s） |
| マウス | 視点（上下 ±85°で制限） |
| `F` | 懐中電灯 ON/OFF |
| `E` | 調べる（画面中央の対象） |
| `Esc` | マウスカーソル解除（クリックで再ロック） |

速度・感度・ヘッドボブの強さはすべて `Player` の Inspector（LightFPSController）で調整できます。

## 3-3. 「調べられる物」を作る（人形・襖・手紙…）
1. 対象オブジェクト（例：日本人形）を選択 → Inspector 下部の **`Add Component`** → `Interactable` と検索して追加
2. `Prompt` に表示文言（例：「市松人形を調べる」）を書く
3. 対象に **Collider があること**を確認（無ければ `Add Component > Box Collider`）。PlayerInteractor は Trigger を無視する設定なので、`Is Trigger` はOFFの通常Colliderを使ってください
4. 再生して近づき、画面中央に捉えて `E` → Console に `[調べる] ○○ : 市松人形を調べる` と出れば成功
5. 実際に何か起こすには、Interactable の **`On Interact` 欄の `+`** を押し、起こしたい処理を登録します（例：次の襖の開閉、音を鳴らす、オブジェクトの表示切替）。コードは不要です

## 3-4. 襖・障子を開けられるようにする
1. 襖オブジェクトに `Add Component > Simple Door` を追加
2. `Door Type` は **`Slide`**（襖・障子・引き戸用）、`Slide Offset` は横方向に開く量（例：X=0.9。向きは実際に再生して確認し、逆なら -0.9）
3. 同じ襖に `Interactable` も追加し、`On Interact` に **その襖自身**をドラッグして `SimpleDoor > Toggle()` を選ぶ
4. これで `E` を押すたびにスッと開閉します。洋風ドアは `Door Type: Swing` にし、蝶番位置に置いた空オブジェクトの方にコンポーネントを付けてください
5. ⚠️ この襖は **Static（特にOccluder Static）を外す**こと（【2】の注意参照）

## 3-5. 「調べる」の表示文を画面に出す（任意・10分作業）
1. `Hierarchy 右クリック > UI > Canvas` → その中に `UI > Text - TextMeshPro`（初回はTMP Importの案内が出るので従う）
2. テキストを画面中央やや下に配置し、中央に小さい「・」（照準）を置く
3. 接続はコード数行です。`PlayerInteractor` の `PromptChanged` イベントに登録すると、対象を捉えた瞬間だけ文言が届きます：

```csharp
using MimiHorror.Interaction;
using TMPro;
using UnityEngine;

public class PromptUI : MonoBehaviour
{
    [SerializeField] private PlayerInteractor interactor;
    [SerializeField] private TextMeshProUGUI promptText;

    private void OnEnable()  => interactor.PromptChanged += OnPromptChanged;
    private void OnDisable() => interactor.PromptChanged -= OnPromptChanged;

    private void OnPromptChanged(string prompt)
    {
        promptText.text = string.IsNullOrEmpty(prompt) ? "" : $"[E] {prompt}";
    }
}
```

## 3-6. なぜこのコードが軽いのか（設計メモ）
- `GetComponent` は **Awakeで1回だけ**。`Update` 内の検索・`Find`系はゼロ
- Raycast は **0.08秒に1回**だけ。同じ物を見続けている間はコンポーネント検索も再実行しない（キャッシュ）
- 物理は `CharacterController.Move` のみ。Rigidbody の連続衝突計算を持ち込んでいない
- マウス感度に `Time.deltaTime` を掛けない → フレームレートが変動しても視点の重さが変わらず、**カクつき知覚が大幅に減る**
- 移動は `SmoothDamp`、重力は接地時に吸着値を入れる方式で、段差降りの浮き・ガタつきを防止
- ドアは開閉アニメーション中だけコルーチンが回り、待機中コストはゼロ
